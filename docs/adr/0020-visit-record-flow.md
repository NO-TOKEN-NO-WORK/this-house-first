# ADR-0020: 방문 기록 흐름 — 고르고 한 번 저장, 끝난 방문은 되읽기

- **상태**: 승인됨
- **날짜**: 2026-08-23
- **결정자**: 팀 전원

## 맥락 (Context)

`/today` 카드의 `방문하기` 흐름 디자인이 Figma `junction`에 네 화면으로 나왔다.

| Figma 노드 | 화면 | 구현 경로 |
|---|---|---|
| `113:2222` | 방문하기 — 기록 전 | `VisitDetailView` (`/today/[subjectId]`) |
| `115:2534` | 방문하기 — 결과·냉방기 선택 상태 | 같은 화면의 선택 상태 |
| `115:2776` | 저장 이후 보드 — 완료 카드 | `SubjectCard`의 `visitRecorded` |
| `123:2971` | 방문 기록 — 끝난 방문 되읽기 | `/today/[subjectId]?view=record` |

기존 구현(ADR-0014 시점)과 네 곳이 어긋났다.

1. **저장 방식**: 구현은 결과 버튼을 누르는 즉시 저장했다. 디자인은 결과·냉방기·메모를 고른 뒤 `저장하기` 한 번이다. 같은 날 머지된 통화 결과 시트(`CallResultSheet`, Figma 99:1267)는 이미 후자다 — 두 흐름이 서로 다른 저장 규칙을 갖게 됐다.
2. **섹션 순서·구성**: 구현은 `메모 → 결과` 순이고 냉방기 점검 섹션이 없다. 디자인은 `결과 → 냉방기 설비 상태 점검 → 메모 → 저장하기`다.
3. **결과 목록**: 구현은 `정상 / 조치함 / 에어컨 없음·고장 / 119 연계`(PRD F4 원문). 디자인은 `괜찮았어요 / 걱정돼요 / 안 계셨어요 / 119 신고`다. `걱정돼요`·`안 계셨어요`는 `VisitResult`에 없던 값이다.
4. **저장 이후**: 구현은 완료 카드에 누를 수 없는 버튼 두 개(`방문하기`·`전화하기`)를 회색으로 남긴다. 디자인은 `방문 완료 기록 보기` 하나로 바꾸고, 누르면 `123:2971`로 간다.

## 결정 (Decision)

- **고르고 한 번 저장한다.** 결과·냉방기 상태를 모두 고르기 전에는 `저장하기`가 비활성이다. `CallResultSheet`와 같은 계약이라 두 흐름이 같은 규칙으로 움직인다.
- **섹션 순서는 Figma를 따른다**: 요약 → 등급 상승 안내 → 위험 사유 → 방문 체크리스트 → 방문 히스토리 → `방문 상황을 기록하세요` → `냉방기 설비 상태 점검` → `메모 (선택)` → `저장하기`. "왜 위험한가 → 무엇을 볼 것인가 → 무엇을 기록할 것인가" 한 방향이다.
- **결과 문구를 `VISIT_RESULT_LABEL`에 반영한다**: `정상 → 괜찮았어요`, `119 연계 → 119 신고`. ADR-0014가 `CALL_RESULT_LABEL`에 한 것과 같은 이유·같은 방법이다 — 화면에 문자열을 박는 대신 상수를 고쳐 시트·상세(`RecordGrid`)·기록 목록·관리자 화면이 함께 따라온다. 저장되는 값(`OK`·`EMERGENCY_119`)은 그대로라 DB·API는 바뀌지 않는다.
- **`VisitResult.SYMPTOM`(걱정돼요)·`VisitResult.ABSENT`(안 계셨어요)를 추가한다.** 둘 다 **방문 큐에 그대로 남긴다**(`HouseholdStatus.VISIT_QUEUED`). 조치 완료로 닫으면 아무도 다시 가지 않는다. 이미 큐에 있던 가구라 새 승격(`promoted`)이 아니다 — 관리자 알림이 중복으로 나가지 않는다.
- **그리드에 내미는 결과는 `VISIT_RECORD_RESULTS` 4개**(`괜찮았어요`·`걱정돼요`·`안 계셨어요`·`119 신고`)로 도메인이 정한다. `조치함`·`에어컨 없음·고장`은 값으로 남되 상세 화면(`RecordGrid`)에서만 고른다 — 화면이 순서를 다시 쓰지 않는다.
- **냉방기 상태를 방문에서도 받는다.** `POST /api/checks`의 `coolingStatus`가 전화 전용이던 제약을 푼다. `에어컨 없음·고장` 결과가 하던 일(FR-8 익일 가중, FR-11 지원사업 플래그)을 이제 방문 화면에서도 `CoolingStatus`가 한다 — 저장 경로는 이미 있는 `coolingStatusSubjectPatch` 하나다.
- **끝난 방문은 되읽기 화면으로 간다.** 방문으로 그날 대응이 끝난 카드는 `방문 완료 기록 보기` 하나만 내밀고 `?view=record`로 이동한다. 되읽기 화면은 같은 레이아웃에 기록한 결과를 눌린 상태로 두고 입력을 잠근다.
- **완료 카드 판정은 상태가 아니라 마지막 확인 종류로 한다.** `119 연계`는 전화에서도 나오는 종결 상태라 상태만으로는 못 가른다. `BoardSubject.lastCheckKind`를 더해 `!open && lastCheckKind === VISIT`일 때만 되읽기 버튼을 보인다.

## 근거 (Rationale)

- 즉시 저장은 탭 1회로 끝나 빨라 보이지만, 잘못 누른 결과가 그대로 상태머신을 통과한다. 되돌리려면 조치 완료 가구에 다시 기록해야 하는데 상태머신이 그걸 막는다(`NOT_VISITABLE`) — 60대 사용자 기준(PRD §9)에서 되돌릴 수 없는 원터치는 안전한 설계가 아니다. `저장하기`는 탭을 하나 늘리는 대신 누른 것을 눈으로 확인할 시간을 준다.
- `걱정돼요`·`안 계셨어요`를 조치 완료로 닫으면 그날의 미처리 수(PRD §11 북극성)가 실제보다 좋아 보인다. 방문 큐에 남기면 보드가 계속 그 가구를 위에 올려 준다.
- 냉방기 점검을 방문에서도 받는 것은 오히려 원래 자리다 — 에어컨 상태를 눈으로 확인할 수 있는 사람은 문 앞에 선 담당자다.

## 검토한 대안 (Alternatives)

- **결과 문구를 Figma대로 화면에 하드코딩** — 도메인 규칙 2 위반. 기각
- **`걱정돼요`를 즉시 승격(`promoted: true`)으로 처리** — 이미 방문 큐에 있는 가구를 다시 승격시켜 관리자 알림이 중복된다. 기각
- **되읽기 화면에서 다시 저장할 수 있게 허용** — `VISITABLE`에 종결 상태를 넣어야 하는데, 그러면 이미 119로 넘어간 가구에도 방문 결과를 덮어쓸 수 있다. 기각
- **`조치함`·`에어컨 없음·고장` 값 제거** — PRD F4의 결과 목록이고 과거 기록(`CheckEvent`)이 이미 그 값을 갖고 있다. 라벨만 두고 그리드에서만 뺀다. 기각

## 결과 (Consequences)

- 긍정: 전화(`CallResultSheet`)와 방문(`VisitDetailView`)이 같은 저장 규칙·같은 섹션 구성을 쓴다. 결과 문구·순서는 `domain.ts` 한 곳이 정한다
- 부정/트레이드오프: 아래 넷은 Figma와 의도적으로 다르며 디자인 리뷰 때 이 ADR을 근거로 설명한다
  1. **`123:2971`의 머리글에 `방문 기록` 제목을 넣는다.** 디자인에는 글자가 없지만 제목 없는 화면은 어디에 있는지 말해 주지 못한다 — 카드 버튼과 같은 말을 쓴다
  2. **되읽기 화면에는 `저장하기`를 두지 않는다.** 디자인에는 있지만 상태머신이 조치 완료 가구의 방문 기록을 막는다. 누를 수 없는 버튼을 남기면 담당자가 저장이 안 된 줄 안다
  3. **되읽기 화면의 냉방기 줄은 아무것도 선택되지 않은 채 잠긴다.** 냉방기 상태는 `Subject`의 두 필드로 옮겨 저장하므로 "그날 무엇을 골랐는지"를 `CheckEvent`에서 되읽을 수 없다. 결과·메모만 되읽는다 (`CheckEvent`에 냉방기 컬럼을 더하려면 마이그레이션이 필요하다 — 필요해지면 새 ADR로)
  4. **메모 자리 표시 글자색**은 Figma의 `action/disabled`(1.55:1) 대신 `text-tertiary`(4.83:1) — ADR-0014의 통화 결과 시트와 같은 이유
- **`걱정돼요`·`안 계셨어요`로 저장하면 카드가 눈에 띄게 바뀌지 않는다** — 방문 큐에 그대로 남으므로 `방문하기` 버튼이 계속 보인다. 무응답 1회 카드처럼 진행 한 줄(`retryNote`)을 붙이는 것이 다음 후보지만 디자인에 해당 화면이 없어 이번 범위 밖이다
- 되돌리기: 문구·그리드 순서는 `domain.ts`, 전이는 `escalation/transition.ts`, 화면은 `VisitDetailView`에 격리돼 있어 각각 독립적으로 되돌릴 수 있다
