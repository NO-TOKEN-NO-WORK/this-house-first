# ADR-0009: 테스트는 Vitest로, 핵심 로직만 단위 테스트한다

- **상태**: 승인됨
- **날짜**: 2026-08-22
- **결정자**: 팀 전원

## 맥락 (Context)

48h 안에 전면적인 테스트는 불가능하지만, 두 모듈은 틀리면 시스템 전체가 무의미해진다: **스코어링 엔진**(FR-3 — 등급이 틀리면 방문 자원이 엉뚱한 곳에 감)과 **에스컬레이션 상태머신**(FR-5 — 승격이 안 되면 무응답 가구가 방치됨). 둘 다 순수 함수로 설계되어 있다([ADR-0005](0005-rule-based-risk-model.md)).

## 결정 (Decision)

**Vitest**를 도입하고, 테스트 범위를 다음으로 한정한다:

- `src/lib/scoring/` — 가중치 적용·등급 분류·reasons 생성
- `src/lib/` 상태머신 — 전이 규칙(무응답 2회→방문큐, 이상 징후→즉시 승격)

UI·E2E 테스트는 하지 않는다. 테스트 파일은 대상 옆에 `*.test.ts`로 둔다.

## 근거 (Rationale)

- Jest 대비 설정 제로(ESM·TS 즉시 동작), 실행 속도 빠름
- 순수 함수 테스트는 작성 비용이 낮고 회귀 방지 효과가 가장 큼
- CI에서 `npm test`로 PR마다 검증

## 검토한 대안 (Alternatives)

- **Jest** — ESM/TS 설정 비용, Vitest 대비 이점 없음. 기각
- **테스트 없음** — 스코어링 오류는 데모 중 눈으로 발견 불가능(숫자가 그럴싸해 보임). 기각
- **Playwright E2E** — 48h 범위 초과. 기각

## 결과 (Consequences)

- 긍정: 핵심 도메인 회귀 방지, PR 검증 자동화
- 부정/트레이드오프: UI 버그는 수동 확인에 의존 — 데모 리허설(D2 오후)로 커버
- 되돌리기: 해당 없음 (제거 비용 0)
