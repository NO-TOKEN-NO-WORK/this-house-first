# ADR-0020: 복지 스캔 — Luna 신호 추출 + 규칙 기반 자격 판정

- 상태: 승인됨
- 날짜: 2026-08-22

## 맥락

관리자가 대상자 현장 메모와 냉방 설비 상태를 복지사업에 연결해 검토해야 한다. 자유
서술 메모는 단순 워크플로우만으로 안정적으로 분류하기 어렵지만, LLM이 수급 자격을
직접 결정하면 설명 가능성과 재현성이 떨어진다.

## 결정

- 서버 Route Handler에서 OpenAI Responses API의 `gpt-5.6-luna`를 `high` reasoning,
  `store: false`, strict Structured Outputs로 호출한다.
- Luna는 메모에서 허용된 문제 코드와 원문 근거만 추출한다. 대상자 이름·연락처·주소·
  담당자 이름은 전송하지 않는다.
- 자격 후보 판정은 `src/lib/welfare-scan/eligibility.ts`의 순수 규칙 엔진이 수행한다.
- 복지사업 원문은 한국사회보장정보원 중앙부처 복지서비스 API에서 서버 전용 키로 조회한다.
- 외부 연동 하나가 실패해도 성공한 결과를 반환하고 UI에 부분 실패를 표시한다.
- MVP에서는 스캔 결과를 저장하지 않고, 관리자 수동 실행만 제공한다. 예약 실행은 후속 범위다.

## 근거

LLM이 잘하는 자유 서술 구조화와 규칙 엔진이 잘하는 재현 가능한 자격 비교를 분리한다.
네이티브 `fetch`로 충분해 SDK 의존성을 추가하지 않는다. `store: false`와 최소 필드 전송으로
민감정보 노출 범위를 줄인다.

## 대안

- 규칙만으로 메모 분석: 표현 변형을 놓치므로 제외
- LLM이 수급 자격까지 결정: 재현성과 설명 가능성이 부족해 제외
- OpenAI SDK 추가: 단일 요청에 필요한 이점이 없어 제외
- 결과 DB 저장·Cron 실행: 관리자 수동 검토가 검증된 뒤 추가

## 결과

`OPENAI_API_KEY`와 `PUBLIC_DATA_SERVICE_KEY`가 모두 필요하다. 키가 없거나 외부 API가
실패하면 관리자에게 실패 원인을 표시하며, 모델 출력만으로 자동 신청·확정하지 않는다.
