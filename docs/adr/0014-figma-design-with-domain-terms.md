# ADR-0014: 담당자 화면은 Figma 디자인을 따르고, 화면 문구는 도메인 상수를 따른다

- **상태**: 부분 대체됨([ADR-0016](0016-alert-level-labels-advisory-watch-severe.md), [ADR-0019](0019-emergency-only-alert-banner.md))
- **날짜**: 2026-08-22
- **결정자**: 팀 전원

## 맥락 (Context)

담당자 화면(FR-4, PRD F3·F4)의 디자인이 Figma `junction` 파일에 나왔다.

| Figma 노드 | 화면 | 구현 경로 |
|---|---|---|
| `25:4` ① (이전 판 `8:1803`) | 담당자 화면 (경보일) | `/today` |
| `14:2926` ①-b | 같은 화면 · 평상시(비경보일) | `/today` |
| `3:505` ② (기록 버튼은 이전 판 `1:714`) | 대상자 상세 + 원터치 기록 | `/today/[subjectId]` |

디자인을 그대로 옮기려는데 두 곳이 기존 규칙·스키마와 충돌했다.

1. **위험 단계 이름**: 디자인은 위험 단계 칩·필터 탭을 `경고 / 위험 / 주의`로 쓴다. 도메인은 대상자 위험 단계를 `심각 / 경계 / 주의`로, 날씨 축을 **경보 단계** `주의 / 경계 / 심각`으로 표시한다. 같은 단어가 있어도 축과 순서가 달라 문맥으로 구분한다.
2. **비경보일 상태 표시**: ①-b는 요약 `3 / 15`와 카드의 `연락 완료` 칩을 보여준다. 이는 비경보일에도 가구별 당일 상태가 있다는 뜻인데, 스키마상 `HouseholdDayStatus`·`CheckEvent`는 `AlertDay`에 매달려 있어(비경보일에는 `AlertDay` 행 자체가 없다 — 침묵이 스펙, PRD §9) 저장할 자리가 없다.

## 결정 (Decision)

- **레이아웃·색·간격·아이콘은 Figma를 따른다.** 색은 `src/app/globals.css`의 `@theme` 토큰으로 모으고, 아이콘은 인라인 SVG로 넣는다(아이콘 라이브러리 미도입 — ADR 없는 라이브러리 도입 금지 규칙).
- **화면에 쓰는 문구는 `src/lib/domain.ts` 상수를 따른다.** 위험 단계 칩·필터 탭은 `GRADE_LABEL`(`심각`·`경계`·`주의`)을 쓰고 디자인의 색(빨강·주황·회색)만 가져온다. 위험 단계 배지의 위험도 표기는 `GRADE_SEVERITY_LABEL`(`심각 초고위험` 등), 대응 지시는 `GRADE_PLAN`, 결과 버튼은 `CALL_RESULT_LABEL`·`VISIT_RESULT_LABEL`을 그대로 쓴다. 내부 `RiskGrade`·`grade` 값은 숫자 1/2/3을 유지하고 `GRADE_LABEL`이 화면 문구로 매핑한다.
- **경보 배너 문구는 단계에 따라 일반화한다**: `오늘 폭염 {ALERT_LEVEL_LABEL} 단계예요 · 체감 {체감온도}°C`. 디자인의 고정 문구("오늘 폭염 심각 단계예요")는 심각 단계에서만 자연스럽다. 25:4에서 배너는 두 줄에서 **한 줄(Label/18)** 로 줄었고, 빠진 `심각 N명`은 바로 아래 요약 카드가 이미 보여 준다.
- **⑤의 결과 문구를 `CALL_RESULT_LABEL`에 반영한다**: `정상/무응답/이상 징후` → `괜찮았어요/안 받으셨어요/걱정돼요`. 화면에 문자열을 박는 대신 상수를 고쳐 시트·상세(`RecordGrid`)·기록 목록이 함께 따라오게 한다 — 이 ADR이 처음부터 말한 "`domain.ts` 한 곳만 고치면 화면 전체가 따라온다"의 첫 적용 사례다. 저장되는 값(`OK`·`NO_ANSWER`…)은 그대로라 DB·API는 바뀌지 않는다.
- **⑤의 `119 신고`를 위해 `CallResult.EMERGENCY_119`를 추가한다.** 전화 결과에는 없던 값이다. 상태머신은 방문의 `VisitResult.EMERGENCY_119`와 같은 `HouseholdStatus.EMERGENCY_119`로 보내되 **승격이 아니라 종결**로 다룬다 — 이미 응급 체계로 넘어갔으므로 방문 큐에 다시 올리지 않는다.
- **통화 종료는 감지하지 않는다.** 웹은 통화가 끝난 시점을 알 수 없다. `tel:`로 넘어가는 순간 시트로 바꿔 두어 통화를 마치고 돌아오면 시트가 이미 떠 있게 한다. 포그라운드 복귀 이벤트에 매달면 앱이 백그라운드로 가지 않는 환경(데스크톱 데모)에서 아무것도 뜨지 않는다.
- **⑥ 저장 이후 카드는 "왜 아직 안 끝났는지"를 카드 안에서 말한다**: 무응답 1회로 멈춘 가구에 `무응답 1회 · 9시 10분` 배너를 붙이고 전화 버튼을 `다시 전화하기`(주 행동, `action-primary`)로 바꾼다. 배너 문구의 앞부분은 `HOUSEHOLD_STATUS_LABEL`이 만든 `statusLabel`을 그대로 쓴다(도메인 규칙 2). 시각은 `formatClockTime`이 `CheckEvent.createdAt`(UTC)을 KST로 옮겨 만든다 — Figma에 오전/오후 표기가 없어 24시간제다(`14시 30분`).
- **카드 chevron은 읽기 전용 대상자 정보로 이동한다**: `/today/[subjectId]?view=info`에서 위험 사유·방문 체크리스트·최근 히스토리를 보여 주고 기록 버튼은 두지 않는다. `방문하기` CTA의 방문 결과 기록 화면과 `전화하기`의 안내 흐름은 그대로 분리한다.
- **위험 사유 문장은 스코어링 엔진 출력 그대로 싣는다.** ②의 `개인 / 건물 / 기상` 세 줄은 `src/lib/scoring/reasons.ts`가 문장을 **건드리지 않고 분류만** 붙여서 만든다 (AGENTS.md 도메인 규칙 3).
- **비경보일 화면(①-b)은 위험 단계·순서·상태 없이 담당 가구 명단만** 보여준다. 요약은 `담당 가구 N가구`, 전화 버튼은 기록 없이 `tel:` 링크. 비경보일 확인 기록은 이번 범위에서 만들지 않는다.

## 근거 (Rationale)

- 색·간격은 디자인 시스템의 몫이고, **상태값 문구는 도메인의 몫**이다. DB 컬럼이 String이라 도메인 상수·가드가 유일한 방어선이므로(ADR-0013) 화면에서 문구를 새로 만드는 순간 그 방어선이 뚫린다.
- 대상자 위험 단계(심각·경계·주의)와 날씨 경보 단계(주의·경계·심각)는 담당자가 **동시에** 보는 두 축이다. 같은 단어가 있어도 축 이름과 표시 순서로 구분하므로, "오늘 경보 단계가 주의인데 이 사람의 위험 단계는 왜 심각인가"처럼 문맥을 함께 읽는다.
- 비경보일 상태 저장은 스키마 변경(가구 상태를 `AlertDay`에서 떼어내기)을 요구한다. 48h 안에서 그 변경은 상태머신·발령·보드 조회 전체를 건드리므로 별도 ADR이 필요한 규모다.

## 검토한 대안 (Alternatives)

- **디자인 문구를 그대로 하드코딩** — 도메인 규칙 2(상태값 문자열 하드코딩 금지)·용어 통일 위반. 기각
- **`경고/위험/주의`를 도메인 상수로 추가** — 규칙은 지키지만 Figma의 표기가 도메인 위험 단계의 의미·순서와 어긋난다. 기각
- **경보 단계 이름을 바꿔 충돌 회피** — 경보 단계 이름은 기상청 특보 체계(주의보·경보·중대경보)에서 온 것이라 바꿀 수 없다. 기각
- **비경보일 상태를 위해 `HouseholdDayStatus`를 `AlertDay`에서 분리** — 이번 범위 밖. 필요해지면 새 ADR로. 기각

## 결과 (Consequences)

- 긍정: 디자인의 시각 언어를 그대로 얻으면서 상태값·사유 문구의 단일 원본이 유지된다. 디자이너가 위험 단계 이름을 확정하면 `domain.ts` 한 곳만 고치면 화면 전체가 따라온다
- 부정/트레이드오프: 아래 11가지는 Figma와 의도적으로 다르며 디자인 리뷰 때 이 ADR을 근거로 설명한다
  1. 위험 단계 칩·탭은 `경고/위험/주의` 대신 `심각/경계/주의` — 다만 **맥락 브리핑 탭 이름은 Figma의 `AI 요약`을 그대로 쓴다**(`164:7618`, 2026-08-23 결정). 위험 단계는 스코어링 엔진이 정하는 도메인 값이라 화면이 이름을 바꾸면 안 되지만, 브리핑 탭 이름은 저장되는 값이 아니라 화면 라벨이다. `맥락 브리핑`은 기획 문서·ADR·코드 주석의 개념 이름으로 남고(FR-12), 화면 문자열은 `SUBJECT_INFORMATION_LABELS.BRIEFING_TAB` 한 곳이 정한다 — 대상자 상세의 인수인계 카드 제목도 같은 값을 읽어 두 화면이 갈라지지 않는다
  2. 배너는 고정 문구 대신 실제 경보 단계에 맞춘 문구
  3. 비경보일은 `3 / 15` 요약과 `연락 완료` 칩 없이 담당 가구 명단만 표시
  4. **방문 대상 가구(②)에는 `전화 걸기` CTA를 두지 않음** — 위험 단계가 심각한 가구는 전화로 '괜찮다'를 확인하지 않는 것이 설계다(PRD F3). 번호는 연락처 줄에서 누를 수 있다
  5. **④의 위험 단계 칩·연락처 배치**: 칩 문구는 Figma의 `심각` 대신 `GRADE_LABEL`(1번 항목과 같은 이유). 연락처 줄은 Figma가 번호·주소를 반씩 나누지만, 실제 주소(`대구광역시 서구 비산동 1`)가 반칸에 안 들어가 번호를 고정폭으로 두고 남는 폭을 주소가 갖게 했다
  6. **결과 목록이 화면마다 다르다**: ⑤ 시트는 Figma대로 4개(`괜찮았어요`·`걱정돼요`·`안 받으셨어요`·`119 신고`)라 `연락두절`이 없고, 상세 화면(`RecordGrid`, Figma ② `1:812`)은 4개라 `119 신고`가 없다. 두 화면이 각각 5개 값의 부분집합을 보여 준다 — 디자이너 확인이 필요하다
  7. **⑥ 배너를 붙이는 상태는 `무응답 1회` 하나다.** 디자인에 그 경우만 있고, 다른 상태는 카드가 이미 칩(완료)이나 버튼(미착수)으로 말하고 있다. 다른 상태에도 배너가 필요하면 `retryNoteOf` 한 곳만 고치면 된다
  8. **방문 동선(`38:5652`)은 카드에 위험 사유를 싣지 않는다.** 디자인의 카드는 이름·나이·등급 칩·주소·`경로 안내` 버튼뿐이다. 도메인 규칙 3(설명 가능성)은 사유를 **재작성하지 말라**는 규칙이고, 사유 원문은 오늘 보드 카드와 대상자 정보(`?view=info`)에 그대로 남아 한 번 눌러 닿는다. 방문 동선은 "어디부터 어떻게 도는가"를 정하는 화면이라 분류를 여기서 되풀이하지 않는다. 같은 이유로 지도 등급 범례와 정렬 규칙 안내문(`심각 → 경계 → 주의 순으로 방문합니다`)도 두지 않는다 — 색의 뜻은 바로 아래 카드 목록이 말한다
  9. **첨부 파일은 화면만 있고 저장이 없다** — 통화 음성(`163:3468` · `164:9043`)과 방문 사진·음성(`164:8144` · `164:8535`) 둘 다. 담당자가 고른 파일은 그 화면 안에만 남고 `저장하기`로 서버에 올라가지 않는다. 통화 음성은 어르신의 육성이고 방문 사진은 집 안 모습이라, 저장하려면 저장소·보존 기간·열람 권한을 새로 정하는 ADR이 먼저다 — [ADR-0024](0024-subject-context-briefing.md)가 정한 경계는 텍스트 메모까지다. 화면을 먼저 두는 것은 데모에서 "다음은 여기까지 간다"를 보여 주기 위해서다. **그 사실을 화면에 적지는 않는다**(2026-08-23 갱신): `현재 음성 파일은 저장되지 않습니다.` 같은 안내는 Figma에 없는 문구고, 데모에서 먼저 보여 줄 것은 흐름이다. 저장 계약(`onSave`·`/api/checks` 본문)에 파일이 끼어들지 않는다는 사실은 화면 문구가 아니라 테스트가 지킨다(`CallResultSheet.test.tsx`·`VisitAttachments.test.tsx`). ⚠️ 데모를 넘어가려면 이 항목이 먼저 해소돼야 한다 — 담당자에게 아무 표시 없이 첨부가 사라지는 상태이기 때문이다
  10. **방문하기 화면에는 맥락 브리핑 카드를 싣지 않는다** (`164:8144`). ver 5 이전에는 위험 사유 아래 카드로 함께 실었으나(ADR-0024), 개정된 디자인은 문 앞에서 읽을 것을 위험 사유·방문 체크리스트로 좁히고 맥락은 `대상자 정보` 탭에 둔다. 보드 카드의 chevron이 그 화면을 한 번에 열고, 전화 흐름(`CallGuideDialog`)의 대화 추천은 그대로다
  11. **하단 탭은 25:4대로 `오늘`·`방문 동선` 둘**이다. 디자인에 `기록` 탭이 없어 `/today/log`는 화면만 남고 탭에서 빠졌다 — 그 화면을 열면 어느 탭도 활성이 아니다(없는 탭을 켜 두지 않는다). 주의 칩 배경은 Figma가 `action/disabled-strong`을 가리키지만 같은 값(`#9ca3af`)의 `status-neutral`을 쓴다 — 주의는 "비활성"이 아니라 "가장 낮은 단계"다
- 접근성 때문에 아래 열둘도 디자인과 다르게 구현했다 (모두 60대 사용자 기준, PRD §9). 토큰 이름은 ADR-0015의 2층 Semantic 기준이다
  - **경계·주의 칩 글자색**은 흰색(각 2.25:1·2.54:1) 대신 `text-primary`(각 6.92:1·6.14:1). 심각 빨강 칩은 흰색도 4.77:1이라 유지한다
  - **요약 카드의 경계 숫자·라벨**은 Figma의 `status/warning`(`#f29900`, 흰 배경 대비 2.25:1 — 20px 굵은 글자 기준 3:1에도 미달) 대신 `status-warning-strong`(`#9a6200`, 5.09:1). 심각 `status-critical`(4.77:1)과 주의 `text-supporting`(10.3:1)은 Figma 그대로 쓴다
  - **하단 탭의 비활성 글자·아이콘**은 Figma의 `action/disabled`(`#c6cfda`, 흰 배경 대비 1.55:1) 대신 `text-secondary`. 13px 글자가 그 대비로는 읽히지 않는다
  - **비활성 버튼 글자색**은 디자인의 흰색(`surface-soft` 배경 대비 1.24:1) 대신 `text-secondary`(약 4.69:1)
  - **⑤ 메모 입력의 자리 표시 글자색**은 Figma의 `action/disabled`(`#c6cfda`, 흰 배경 대비 1.55:1) 대신 `text-tertiary`(4.83:1). 그 대비로는 예시 문장이 보이지 않는다
  - **⑤ 시트의 손잡이는 버튼이다.** Figma에서는 그림이지만, 끌어서 닫기를 구현하지 않는 한 그림만 두면 시트에 보이는 닫기 수단이 없다. 누르는 자리는 44px 높이다
  - **다이얼로그 닫기 버튼의 누르는 자리는 44px**이다. 글리프는 Figma대로 24px이지만 24px 타깃은 오탭이 난다
  - **방문 동선 지도의 구간 이동시간(`38:5669`)에는 흰 알약 배경을 깐다.** Figma는 배경 없는 맨 글자지만 그 지도는 회색 목업이다. 실제 카카오 타일에는 도로명·건물명이 이미 깔려 있어 배경 없이는 이 화면의 유일한 구간 시간 표시가 읽히지 않는다
  - **확인 기록 상세의 결과 칩은 채운 색 위 흰 글자를 쓰지 않는다.** `status/success`(`#1e8e5a`) 위 흰 15px 글자는 3.9:1이라 `*-subtle` 배경 + `*-strong` 글자로 바꿨다(`RecordGrid`와 같은 짝, 6.3:1). `대화 요약` 배지 글자도 같은 이유로 `status-warning`(2.2:1) 대신 `status-warning-strong`(5.4:1)이다
  - **첨부 파일 지우기의 누르는 자리는 44px**이다. 글리프는 Figma대로 16px이지만 그 크기로는 오탭이 난다. 방문 사진의 `✕`는 그 44px을 썸네일(58px) *안*에 가둔다 — 모서리 밖으로 넓히면 옆 사진의 지우기와 겹쳐 엉뚱한 장이 지워진다
  - **방문 동선 지도 마커의 누르는 자리는 48px**이다. 배지 글리프는 Figma대로 26px이지만 26px 타깃은 지도 위에서 오탭이 난다
  - **기록 실패 메시지는 버튼 그리드 *아래*에 붙인다** — 위에 끼우면 오류가 뜨는 순간 버튼 4개가 밀려 방금 누르려던 자리에 다른 결과 버튼이 들어온다(오탭 사고)
- **25:4에서 해소된 예외 하나**: 위험 단계별 대응 지시("3명 | 전화 생략 · 오전 방문")는 대비 때문에 `text-primary`로 눌러 두었는데, 화면 배경이 `background/subtle`에서 **`surface/default`(흰색)로 바뀌면서** Figma의 단계색을 그대로 쓸 수 있게 됐다(심각 6.59:1 · 경계 5.09:1 · 주의 4.83:1). 배경색 하나가 세 색의 사용 가능 여부를 정한 사례라 되돌릴 때 함께 봐야 한다
- 되돌리기: 문구는 `domain.ts`, 색은 `globals.css` 토큰, 분류는 `scoring/reasons.ts`에 격리돼 있어 각각 독립적으로 되돌릴 수 있다
