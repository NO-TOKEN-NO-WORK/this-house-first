# ADR-0014: 담당자 화면은 Figma 디자인을 따르고, 화면 문구는 도메인 상수를 따른다

- **상태**: 승인됨
- **날짜**: 2026-08-22
- **결정자**: 팀 전원

## 맥락 (Context)

담당자 화면(FR-4, PRD F3·F4)의 디자인이 Figma `junction` 파일에 나왔다.

| Figma 노드 | 화면 | 구현 경로 |
|---|---|---|
| `8:1803` ① | 담당자 · 오늘의 대응 보드 (경보일) | `/today` |
| `14:2926` ①-b | 같은 화면 · 평상시(비경보일) | `/today` |
| `3:505` ② (기록 버튼은 이전 판 `1:714`) | 대상자 상세 + 원터치 기록 | `/today/[subjectId]` |
| `1:883` ③ | 방문 큐 & 출동 경로 | 미구현 (방문 결과 버튼 스타일만 ②에 재사용) |

디자인을 그대로 옮기려는데 두 곳이 기존 규칙·스키마와 충돌했다.

1. **등급 이름**: 디자인은 위험 등급 칩·필터 탭을 `경고 / 위험 / 주의`로 쓴다. 그런데 `주의`는 AGENTS.md 용어 통일에서 이미 **경보 단계**(주의·경보·비상)의 이름이다. 상단 배너가 "폭염 비상 단계"인 화면에서 등급 칩이 "주의"로 뜨면 담당자가 두 축을 같은 축으로 읽는다.
2. **비경보일 상태 표시**: ①-b는 요약 `3 / 15`와 카드의 `연락 완료` 칩을 보여준다. 이는 비경보일에도 가구별 당일 상태가 있다는 뜻인데, 스키마상 `HouseholdDayStatus`·`CheckEvent`는 `AlertDay`에 매달려 있어(비경보일에는 `AlertDay` 행 자체가 없다 — 침묵이 스펙, PRD §9) 저장할 자리가 없다.

## 결정 (Decision)

- **레이아웃·색·간격·아이콘은 Figma를 따른다.** 색은 `src/app/globals.css`의 `@theme` 토큰으로 모으고, 아이콘은 인라인 SVG로 넣는다(아이콘 라이브러리 미도입 — ADR 없는 라이브러리 도입 금지 규칙).
- **화면에 쓰는 문구는 `src/lib/domain.ts` 상수를 따른다.** 등급 칩·필터 탭은 `GRADE_LABEL`(`1등급`·`2등급`·`3등급`)을 쓰고 디자인의 색(빨강·주황·회색)만 가져온다. 등급 배지의 위험도 표기는 `GRADE_SEVERITY_LABEL`(`1등급 초고위험` 등), 대응 지시는 `GRADE_PLAN`, 결과 버튼은 `CALL_RESULT_LABEL`·`VISIT_RESULT_LABEL`을 그대로 쓴다.
- **경보 배너 문구는 단계에 따라 일반화한다**: `오늘은 폭염 {ALERT_LEVEL_LABEL} 단계입니다`. 디자인의 고정 문구("폭염 비상 경보 단계입니다")는 비상 단계에서만 자연스럽다.
- **위험 사유 문장은 스코어링 엔진 출력 그대로 싣는다.** ②의 `개인 / 건물 / 기상` 세 줄은 `src/lib/scoring/reasons.ts`가 문장을 **건드리지 않고 분류만** 붙여서 만든다 (AGENTS.md 도메인 규칙 3).
- **비경보일 화면(①-b)은 등급·순서·상태 없이 담당 가구 명단만** 보여준다. 요약은 `담당 가구 N가구`, 전화 버튼은 기록 없이 `tel:` 링크. 비경보일 확인 기록은 이번 범위에서 만들지 않는다.

## 근거 (Rationale)

- 색·간격은 디자인 시스템의 몫이고, **상태값 문구는 도메인의 몫**이다. DB 컬럼이 String이라 도메인 상수·가드가 유일한 방어선이므로(ADR-0013) 화면에서 문구를 새로 만드는 순간 그 방어선이 뚫린다.
- 등급(1·2·3)과 경보 단계(주의·경보·비상)는 담당자가 **동시에** 보는 두 축이다. 이름이 겹치면 "오늘 주의 단계인데 이 사람은 왜 주의 등급이 아닌가" 같은 오해가 데모 현장에서 바로 나온다. 용어 통일 규칙이 있는 이유가 이것이다.
- 비경보일 상태 저장은 스키마 변경(가구 상태를 `AlertDay`에서 떼어내기)을 요구한다. 48h 안에서 그 변경은 상태머신·발령·보드 조회 전체를 건드리므로 별도 ADR이 필요한 규모다.

## 검토한 대안 (Alternatives)

- **디자인 문구를 그대로 하드코딩** — 도메인 규칙 2(상태값 문자열 하드코딩 금지)·용어 통일 위반. 기각
- **`경고/위험/주의`를 도메인 상수로 추가** — 규칙은 지키지만 `주의`가 두 축에서 서로 다른 뜻이 되는 문제는 그대로. 기각
- **경보 단계 이름을 바꿔 충돌 회피** — 경보 단계 이름은 기상청 특보 체계(주의보·경보·중대경보)에서 온 것이라 바꿀 수 없다. 기각
- **비경보일 상태를 위해 `HouseholdDayStatus`를 `AlertDay`에서 분리** — 이번 범위 밖. 필요해지면 새 ADR로. 기각

## 결과 (Consequences)

- 긍정: 디자인의 시각 언어를 그대로 얻으면서 상태값·사유 문구의 단일 원본이 유지된다. 디자이너가 등급 이름을 확정하면 `domain.ts` 한 곳만 고치면 화면 전체가 따라온다
- 부정/트레이드오프: **Figma와 화면의 문구가 다르다.** 위 4개 항목(등급 이름, 배너 문구, ①-b 요약·상태 칩)은 의도된 차이이며 디자인 리뷰 때 이 ADR을 근거로 설명한다
- 아래 세 가지도 디자인과 다르게 구현했다. 모두 PRD 제약과 충돌해서다
  - **방문 대상 가구(②)에는 `전화 걸기` CTA를 두지 않는다** — 1등급은 전화로 '괜찮다'를 확인하지 않는 것이 설계다(PRD F3). 바로 위 안내와 모순되는 큰 버튼을 없애고, 번호는 연락처 줄에서 누를 수 있게 뒀다
  - **비활성 버튼 글자색**은 디자인의 흰색(`#e2e7ee` 배경 대비 1.3:1) 대신 `--color-ink-soft`(약 4.9:1) — 60대 사용자 기준 접근성(PRD §9)
  - **기록 실패 메시지는 버튼 그리드 *아래*에 붙인다** — 위에 끼우면 오류가 뜨는 순간 버튼 4개가 밀려 방금 누르려던 자리에 다른 결과 버튼이 들어온다(오탭 사고)
- 되돌리기: 문구는 `domain.ts`, 색은 `globals.css` 토큰, 분류는 `scoring/reasons.ts`에 격리돼 있어 각각 독립적으로 되돌릴 수 있다
