# ADR-0022: 상시 원장과 경보 스냅샷을 분리한다

- **상태**: 승인됨
- **날짜**: 2026-08-23
- **결정자**: 팀 전원

## 맥락 (Context)

`Worker`, `Subject`, `Building`은 날짜와 무관한 상시 원장이지만 관리자 조회가 `AlertDay`에 묶여 있어 비경보일에는 대상자가 삭제된 것처럼 보인다. 또한 대상자 물리 삭제는 `RiskAssessment`, `HouseholdDayStatus`, `CheckEvent`까지 지워 과거 관제 기록을 훼손한다.

## 결정 (Decision)

- `Worker`, `Subject`, `Building`은 상시 원장으로, `AlertDay`, `RiskAssessment`, `HouseholdDayStatus`, `CheckEvent`는 날짜별 경보 스냅샷으로 유지한다.
- `Worker`와 `Subject`에 nullable `archivedAt`을 추가한다. `NULL`이면 활성, 시각이 있으면 보관 상태다. 현재 원장과 새 경보 발령에서는 보관된 행을 제외하되 과거 경보 스냅샷과 외래키 관계는 유지한다.
- 대상자 제거는 물리 삭제 대신 `archivedAt`만 기록한다. 생활지원사는 활성 대상자가 없을 때만 같은 방식으로 보관한다.
- 활성 원장 조회를 위해 `Worker(role, archivedAt)`과 `Subject(workerId, archivedAt)` 복합 인덱스를 둔다.
- 마이그레이션은 nullable 컬럼과 인덱스만 추가한다. 기본값, 백필, 데이터 삭제는 없으며 기존 행은 모두 `archivedAt = NULL`인 활성 상태로 보존한다.

## 근거 (Rationale)

원장 생명주기와 경보일 관제 생명주기를 분리하면 비경보일에도 현재 명단을 관리하면서 과거 위험평가·상태·확인 기록을 그대로 보존할 수 있다. nullable 시각 한 필드는 기존 관계와 상태머신을 바꾸지 않는 최소 변경이며 보관 시점도 남긴다.

## 검토한 대안 (Alternatives)

- **조회 코드만 수정** — 비경보일 명단은 보이지만 물리 삭제가 과거 기록을 지우는 문제를 해결하지 못한다.
- **`CareDay`·`SubjectDay` 도입** — 비경보일 확인 기록까지 지원할 때 필요한 구조다. 이번 요구는 상시 원장 관리이므로 새 날짜 엔터티와 상태머신 마이그레이션을 도입하지 않는다.
- **전날 경보 스냅샷 복제** — 과거 위험도와 상태를 오늘 데이터처럼 보여 날짜별 사실성을 깨뜨린다.

## 결과 (Consequences)

- 긍정: 경보 유무와 무관하게 활성 원장을 조회하고, 보관 뒤에도 과거 관제 기록과 관계를 보존한다.
- 부정/트레이드오프: 현재 원장·신규 발령·기본 담당자·알림 수신자 조회마다 `archivedAt: null` 조건이 필요하며, 보관된 행의 별도 복원 UI는 제공하지 않는다.
- 되돌리기: 애플리케이션의 활성 필터와 보관 동작은 되돌릴 수 있다. 컬럼 제거는 보관 이력을 잃으므로 별도 ADR과 데이터 보존 계획 없이는 수행하지 않는다.
