# ADR-0019: 경보 배너는 비상 단계에만 띄우고, 최고 경보 단계 문구는 `비상`으로 되돌린다

- **상태**: 승인됨
- **날짜**: 2026-08-22
- **결정자**: 팀 전원

## 맥락 (Context)

담당자 보드(`/today`, PRD F3)의 최신 Figma 시안 두 장이 지금 구현과 어긋난다.

| Figma 노드 | 화면 | 배너 |
|---|---|---|
| `38:4482` | 담당자 보드 · 최고 단계 경보일 | `오늘 폭염 비상 단계예요 · 체감 38°C` (빨강 Pill) |
| `133:3213` | 담당자 보드 · 그 아래 단계 경보일 | **배너 없음** — 인사말 바로 아래가 요약 카드 |

지금 구현은 [ADR-0014](0014-figma-design-with-domain-terms.md)를 따라 배너를 **모든 경보일에** 띄우고 색만 단계별로 바꿨고, 문구는 [ADR-0016](0016-alert-level-labels-advisory-watch-severe.md)의 `ALERT_LEVEL_LABEL`을 따라 `오늘 폭염 심각 단계예요`였다.

문제는 두 시안이 같은 화면에서 드러낸다. 배너 바로 아래 요약 카드는 **위험 단계** 숫자를 `심각 2명 · 경계 2명 · 주의 1명`으로 보여 준다. 배너까지 `심각 단계`라고 말하면 한 화면에 축이 다른 `심각`이 둘이다 — 담당자는 배너의 `심각`을 아래 `심각 2명`과 같은 것으로 읽는다. ADR-0016이 감수하기로 한 "같은 단어를 문맥으로 구분한다"가 실제 레이아웃에서는 두 단어가 **세로로 붙어** 나와 성립하지 않는다.

## 결정 (Decision)

- **배너는 `AlertLevel.EMERGENCY`에서만 렌더한다.** 주의·경계 단계에서는 색을 바꾸는 게 아니라 배너 자체를 그리지 않는다 (`EmergencyBanner`가 `null` 반환). 단계별 배너 색 표(`LEVEL_BANNER`)는 지운다 — 남는 색은 `status-critical` 하나다.
- **`ALERT_LEVEL_LABEL.EMERGENCY`를 `비상`으로 되돌린다.** `ADVISORY`(주의)·`WARNING`(경계)은 그대로다. 이 표가 여전히 유일한 원본이므로 배너·아침 알림 제목·위험 사유 문장·관리자 발령 버튼·API 오류 문구가 함께 따라온다.
- **내부 코드와 DB는 손대지 않는다.** `AlertDay.level`은 `ADVISORY`/`WARNING`/`EMERGENCY`를 그대로 저장한다. 마이그레이션 없음.
- 이 결정은 ADR-0014의 「경보 배너 문구는 단계에 따라 일반화한다」와 ADR-0016의 `EMERGENCY → 심각` 한 줄을 대체한다. 두 ADR의 나머지(Figma 레이아웃 규칙, `GRADE_LABEL`, 주의·경계 문구, 사유 문장 규칙)는 유지한다.

| 코드 | 화면 문구 | 배너 |
|---|---|---|
| `ADVISORY` | 주의 | 없음 |
| `WARNING` | 경계 | 없음 |
| `EMERGENCY` | 비상 | `오늘 폭염 비상 단계예요 · 체감 N°C` |

## 근거 (Rationale)

- **매 경보일 떠 있는 빨간 띠는 곧 배경이 된다.** 배너의 값은 "오늘은 평소와 다르다"는 신호인데, 주의·경계까지 띄우면 그 신호가 상시 표시로 희석된다. 낮은 단계에서 무엇부터 할지는 요약 카드와 위험 단계 필터가 이미 말한다 — 화면당 결정 1개(PRD §9)에도 맞다.
- **경보 단계와 위험 단계가 세로로 붙는 자리에서는 단어가 겹치면 안 된다.** 최댓값만 다른 단어(`비상`)를 쓰면 두 축이 눈으로 갈린다. ADR-0016이 `비상`을 기각한 이유는 `HouseholdStatus.EMERGENCY_119`와의 충돌이었는데, 그 값의 화면 문구는 `119 연계`·`119 신고`라서 **화면에서는 `비상`과 겹치지 않는다**. 겹치는 것은 내부 코드 이름뿐이고, 내부 코드는 이 결정이 건드리지 않는다.
- 기상청 특보 명칭(주의보·경보·중대경보)은 `weights.ts`의 임계값 인용에만 쓰므로 가중치 방어(PRD §7)는 그대로다.

## 검토한 대안 (Alternatives)

- **배너를 모든 경보일에 유지하고 색만 바꾸기(현행)** — Figma `133:3213`에 배너가 없다. 상시 표시가 신호를 죽인다. 기각
- **`심각` 유지 + 배너에서만 `비상`으로 표기** — 한 값에 화면 문구가 둘이 되어 `domain.ts` 단일 원본(도메인 규칙 2)이 깨진다. 기각
- **위험 단계 라벨(`GRADE_LABEL`)을 바꿔 충돌 회피** — ADR-0014가 이미 검토·확정한 축이고, 카드·칩·필터·요약까지 전부 흔든다. 배너 한 값을 바꾸는 쪽이 싸다. 기각
- **배너를 접이식(요약만 남기고 펼치기)으로** — 60대 사용자에게 탭 하나를 더 요구한다. 기각

## 결과 (Consequences)

- 긍정: 최고 단계 경보일에만 화면이 눈에 띄게 달라져 배너가 신호로 남는다. 한 화면의 `심각`이 위험 단계 하나로 정리된다
- 부정/트레이드오프
  - 주의·경계 경보일에는 **당일 체감온도가 담당자 보드에서 사라진다.** 온도는 위험 사유 문장(`오늘 비상 단계 (체감 38도)` 등)과 대상자 상세에 남는다 — 보드 상단에서 온도를 다시 보여 달라는 요구가 오면 요약 카드에 넣는다
  - 화면 문구 `비상`과 내부 코드 `EMERGENCY_119`(119 연계)가 영어로는 같은 단어를 쓴다. 화면에서는 갈리지만 코드를 읽을 때는 주석에 의존한다
  - ADR-0016 본문은 `심각`을 그대로 둔 역사 기록으로 남는다 (상태: 부분 대체됨)
- 되돌리기: `domain.ts`의 `ALERT_LEVEL_LABEL`과 `src/app/today/page.tsx`의 `EmergencyBanner` 조건 두 곳이면 된다. DB·API·마이그레이션 영향 없음
