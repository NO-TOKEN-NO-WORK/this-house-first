# ADR-0018: 방문 동선은 카카오 자동차 최단 경로를 쓴다

- **상태**: 승인됨
- **날짜**: 2026-08-22
- **결정자**: 팀 전원
- **대체**: [ADR-0007](0007-kakao-map.md)의 도보 경로·직선거리 정렬 결정

## 맥락 (Context)

FR-7은 방문 큐가 2건 이상일 때 위험도 우선 + 이동시간 최소 순서와 출동 경로를 제시해야 한다. 기존 구현은 직선거리로 순서를 정하고 도보 경로로 선을 보강해, 일방통행·교량·차량 진입 가능 도로와 실제 차량 이동시간을 반영하지 못한다. 현장 출동 수단은 차량이므로 표시 경로와 방문 순서 모두 자동차 도로망을 기준으로 해야 한다.

## 결정 (Decision)

서버 Route Handler에서 카카오모빌리티 길찾기 API를 호출한다. 다중 목적지 API(`POST /v1/destinations/directions`)의 `DISTANCE` 결과로 실제 차량 도로거리 행렬을 만들고, 첫 방문지는 가장 위험 점수가 높은 가구로 고정한다. 이후 위험 단계(심각 → 경계 → 주의) 순서를 지키는 조합 중 총 도로거리가 가장 짧은 순서를 계산한다. 확정 순서는 다중 경유지 API(`POST /v1/waypoints/directions`)의 `DISTANCE` 경로로 보강해 구간별 거리·시간·도로 좌표를 표시한다.

`KAKAO_REST_KEY`는 서버 전용으로 유지한다. 키 누락·외부 API 실패 시 화면 전체를 실패시키지 않고 기존 직선거리 예상치로 폴백한다.

## 근거 (Rationale)

1. 카카오모빌리티 공식 자동차 길찾기는 `DISTANCE`(최단 경로)를 제공하고, 상세 응답의 `sections[].roads[].vertexes`로 실제 도로 선을 그릴 수 있다.
2. 다중 목적지는 한 출발지에서 최대 30개 목적지까지 거리·시간을 반환하므로, 담당자 1인의 최대 15가구 거리 행렬을 출발지당 한 요청으로 만들 수 있다.
3. 위험 단계 우선은 PRD F4의 안전 제약이므로 순수 거리 최적화보다 먼저 적용한다. 같은 제약을 만족하는 순서만 비교하면 차량 동선 개선과 도메인 규칙을 함께 지킬 수 있다.
4. [ADR-0007](0007-kakao-map.md)은 자동차 길찾기에 제휴 승인이 필요하다고 보고 v0에서 제외했지만, 이 저장소의 `KAKAO_REST_KEY`만으로 다중 목적지·다중 경유지 API 실호출이 성공했다(2026-08-22 확인). 도보로 우회할 이유가 사라졌다.

## 검토한 대안 (Alternatives)

- **직선거리 최근접 순서 + 직선 Polyline** — 호출이 없지만 실제 도로와 다르고 사용자 요청을 충족하지 못해 기각
- **도보 경로** — 좁은 길 표현에는 유리하지만 차량 진입 제약·예상시간이 달라 기각
- **카카오 TMS 배차 최적화** — 더 복잡한 배차 제약을 지원하지만 15가구 단일 담당자 MVP에는 제품·계약 범위가 과해 기각
- **`priority`를 `TIME`·`RECOMMEND`로** — PRD §5 F4는 "이동시간 최소"라고 쓴다. 그럼에도 거리 기준을 택한 이유는 동 단위 구간이 짧아 시간 차이가 신호등·실시간 교통에 좌우돼 데모마다 순서가 흔들리는 반면 도로거리는 재현 가능하기 때문이다. 화면의 `예상 이동 N분`은 확정 순서의 실제 응답 `duration` 합이라 시간 정보 자체는 그대로 보여 준다. 시간 기준으로 되돌릴 때는 `priority` 값과 이 ADR을 함께 바꾼다
- **브라우저 현재 위치부터 전역 최단 순회** — 위치 권한과 출발 시점 상태가 추가로 필요하다. v0는 가장 위험한 첫 가구부터의 가구 간 동선만 계산하고, 개별 `경로 안내` 링크가 현재 위치를 출발지로 받는다

## 결과 (Consequences)

- 지도 선, 구간 거리, 예상 이동시간이 실제 자동차 도로망을 반영한다.
- 방문 순서 계산에 최대 방문 가구 수만큼 다중 목적지 요청 + 상세 경로 1회가 필요하다. API 지연·쿼터를 모니터링해야 한다.
- 다중 목적지 탐색 반경은 공식 최대값인 10km다. 한 담당자의 동 단위 배정이라는 현재 데이터 범위에는 맞지만 광역 배정으로 확장하면 분할 또는 TMS를 재검토한다.
- 외부 API가 실패해도 방문 목록과 위험 단계 순서는 유지되며 화면은 직선거리 추정치로 폴백한다.
- ~~화면에는 계산 중/추정 경로가 표시된다~~ — 방문 동선 화면을 Figma `38:5652`에 맞추면서
  경로 출처 캡션(`카카오모빌리티 자동차 최단 경로 기준` / `자동차 경로를 계산하는 중` /
  `차량 경로를 불러오지 못해 직선거리 예상치`)을 걷어냈다. 디자인에 그 자리가 없다.
  대가로 담당자는 화면만 보고 실측 경로와 추정치를 구분할 수 없고, 카카오 응답이 도착해
  방문 순서가 재정렬될 때 예고가 없다. 구분이 필요해지면 캡션을 되살리는 대신
  디자이너와 표시 자리를 먼저 정한다.
- 폴백 예상치(`src/lib/map/route.ts`)는 도보값이 아니라 같은 날 실측한 차량값(직선거리 1.6배·319m/분)을 쓴다. 도보값을 두면 예상 이동시간이 실제보다 약 28% 짧게 나온다.
