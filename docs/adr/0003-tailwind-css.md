# ADR-0003: 스타일링은 Tailwind CSS 4로 한다

- **상태**: 승인됨
- **날짜**: 2026-08-22
- **결정자**: 팀 전원

## 맥락 (Context)

담당자 화면은 60대 사용자 기준의 강한 접근성 요구가 있다(PRD §9: 큰 글자, 화면당 결정 1개, 2탭 이내). 관리자 대시보드는 지도+위젯 레이아웃이 필요하다. 48h 안에 두 화면을 디자이너 없이 만들어야 한다.

## 결정 (Decision)

**Tailwind CSS 4** (create-next-app 기본 구성 유지). 담당자 화면의 접근성 규칙(최소 글자 크기, 터치 타깃 크기)은 `globals.css`의 디자인 토큰과 공용 컴포넌트로 강제한다. 컴포넌트 키트가 필요해지면 shadcn/ui를 부분 도입한다(별도 ADR 불요 — Tailwind 위 복사-붙여넣기 방식이므로).

## 근거 (Rationale)

- 별도 CSS 파일 왕복 없이 화면을 빠르게 조립 — 해커톤 표준
- 유틸리티 클래스는 AI 에이전트가 생성·수정하기에 가장 예측 가능한 스타일 방식

## 검토한 대안 (Alternatives)

- **CSS Modules** — 파일 왕복 비용, 토큰 강제 어려움. 기각
- **MUI/Ant Design** — 무겁고 커스텀(큰 글자 모바일 UI)과 싸우게 됨. 기각

## 결과 (Consequences)

- 긍정: 스타일 작업 속도, 번들 최소화
- 부정/트레이드오프: 클래스 나열로 마크업 가독성 저하 — 공용 컴포넌트 추출로 완화
- 되돌리기: 화면 수가 적어 이전 비용 낮음, 그러나 48h 내에는 확정
