# ADR-0016: 경보 단계 화면 문구는 주의/경계/심각으로 표시한다

- **상태**: 승인됨
- **날짜**: 2026-08-22
- **결정자**: 팀 전원

## 맥락 (Context)

경보 단계(PRD F1)의 세 값은 내부 코드 `ADVISORY` / `WARNING` / `EMERGENCY`로 저장되고, 화면 문구는 `ALERT_LEVEL_LABEL`이 맡는다. 기존 표시는 주의/경보/비상이다.

축 이름 **경보 단계**와 중간값 **경보**가 같고, 최댓값 **비상**은 `HouseholdStatus.EMERGENCY_119`(119 연계)와 겹친다. 담당자는 같은 화면에서 경보 단계·위험 단계·가구 상태를 동시에 본다(PRD F3·ADR-0014).

[ADR-0014](0014-figma-design-with-domain-terms.md)는 대안 「경보 단계 이름을 바꿔 충돌 회피」를 기각했다. 이유는 「경보 단계 이름은 기상청 특보 체계(주의보·경보·중대경보)에서 온 것이라 바꿀 수 없다」였다. 그 문장은 **축 이름과 임계값 출처**에는 맞지만, **화면 세 값**까지 특보 명칭과 1:1로 묶을 필요는 없다.

## 결정 (Decision)

- **화면 문구**는 `주의` / `경계` / `심각`이다. `ALERT_LEVEL_LABEL`이 유일한 원본이다.
- **내부 코드**는 `ADVISORY` / `WARNING` / `EMERGENCY`를 유지한다. DB `AlertDay.level`은 이 코드를 저장한다.
- **기상청 출처 용어** 주의보 / 경보 / 중대경보 / 폭염특보는 임계값 인용에 그대로 둔다 (`weights.ts` HEAT_ALERT_THRESHOLD).
- **축 이름**은 경보 단계다. 대상자 **위험 단계 칩**은 `심각` / `경계` / `주의`다 (ADR-0014).
- 대상자 위험 단계의 내부 `RiskGrade`·`grade` 숫자 1/2/3은 유지하고, `GRADE_LABEL`이 각각 `심각` / `경계` / `주의`로 매핑한다.
- 이 결정은 ADR-0014가 기각한 「경보 단계 이름은 바꿀 수 없다」를 **화면 문구에 한해** 대체한다. ADR-0014의 나머지(Figma 레이아웃, `GRADE_LABEL`, 사유 문장 규칙)는 유지한다.

| 코드 | 화면 문구 |
|---|---|
| `ADVISORY` | 주의 |
| `WARNING` | 경계 |
| `EMERGENCY` | 심각 |

## 근거 (Rationale)

- 축(경보 단계)과 값(경계)이 겹치지 않으면 "오늘 경보 단계인데 이 사람은 왜 경보인가" 같은 오해가 사라진다
- 대상자 위험 단계와 경보 단계가 같은 심각·경계·주의 단어를 쓰더라도, 축 이름과 표시 순서를 함께 보여 문맥으로 구분한다
- 심각과 119 연계가 같은 글자를 쓰지 않는다
- 코드·DB를 바꾸지 않으므로 마이그레이션이 없다. 특보 인용은 그대로라 가중치 방어(PRD §7)도 깨지지 않는다

## 검토한 대안 (Alternatives)

- **주의/경보/비상 유지** — 축·중간값·119 연계와 글자가 겹친다. 기각
- **축 이름을 경계 단계로 바꾸기** — 축은 경보 단계다. 이번 범위 밖. 기각
- **내부 코드를 WATCH/SEVERE로 바꾸기** — 화면만의 문제인데 DB 문자열을 옮긴다. 기각
- **위험 단계 칩을 경고/위험/주의로 되돌리기** — ADR-0014가 이미 기각. 도메인 표기인 심각/경계/주의를 유지

## 결과 (Consequences)

- 긍정: 배너·사유·발령 버튼·API 오류 문구가 `ALERT_LEVEL_LABEL`을 따라 주의/경계/심각으로 맞춰진다
- 부정/트레이드오프: ADR-0014 본문은 당시 Figma 문구와 용어 충돌을 역사 기록으로 남긴다. 비경보일·경보 단계·위험 단계 같은 개념어는 현재 결정에 맞춘다
- 되돌리기: `src/lib/domain.ts`의 `ALERT_LEVEL_LABEL`과 테스트 fixture를 되돌리면 된다. DB 코드는 그대로다
