# ADR-0005: 위험도 모델은 규칙 기반으로 구현한다 (ML 배제)

- **상태**: 승인됨
- **날짜**: 2026-08-22
- **결정자**: 팀 전원

## 맥락 (Context)

PRD §7이 위험도 모델 v0를 곱셈형 규칙(`개인 × 건물 × 기상`)으로 명시한다. 목표는 사망 "예측"이 아니라 확인 자원의 "배분"이며(PRD §3 비목표), 담당자 카드에 위험 사유를 사람이 읽을 수 있게 표시해야 한다(F3 — "설명 가능성이 신뢰의 조건"). 학습에 쓸 라벨 데이터도 없다.

## 결정 (Decision)

위험도는 **순수 함수 규칙 엔진**으로 구현한다. 구현 규칙:

1. 모든 가중치는 `src/lib/scoring/weights.ts` **한 파일에서만** 정의하고, 각 가중치에 **출처를 주석으로 명기**한다(PRD §7 필수 요구 — "가중치 어떻게 정했나" 방어).
2. 스코어링 함수는 점수와 함께 **위험 사유 문자열 배열(reasons)** 을 반환한다. UI는 이 reasons만 표시한다.
3. DB·네트워크에 의존하지 않는 순수 함수로 유지하고 Vitest로 단위 테스트한다([ADR-0009](0009-vitest.md)).

## 근거 (Rationale)

- 근거(질병청·Vandentorren 2006·Fouillet 2008) 기반 가중치는 심사 질문에 방어 가능
- 순수 함수라서 합성 데이터 15명 전체에 대한 표 형태 검증이 쉬움
- "현행(무작위 순서)보다 나으면 됨" — 랭킹 문제는 규칙으로 충분(PRD §12)

## 검토한 대안 (Alternatives)

- **ML 모델** — 라벨 없음, 설명 불가, 48h 낭비, PRD가 명시적으로 배제. 기각
- **가중 합산(덧셈형)** — PRD §7이 곱셈형을 명시(위험 요인의 상호 증폭 반영). 기각

## 결과 (Consequences)

- 긍정: 설명 가능, 테스트 가능, 심사 방어 가능
- 부정/트레이드오프: 1/2/3등급 컷오프 임계값은 PRD에 근거가 없음 → 합성 데이터 15명의 점수 분포와 담당자 처리 능력(방문 ~4가구/일, PRD P3)을 보고 D1에 캘리브레이션해야 함. 임계값은 `weights.ts`에 잠정치로 두고 "잠정" 주석을 유지한다
- 되돌리기: 실데이터 축적 후 재학습이 로드맵(PRD §7) — reasons 인터페이스를 유지하는 한 엔진 교체 가능
