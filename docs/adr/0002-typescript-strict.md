# ADR-0002: TypeScript strict 모드를 쓴다

- **상태**: 승인됨
- **날짜**: 2026-08-22
- **결정자**: 팀 전원

## 맥락 (Context)

핵심 도메인이 문자열 상태값으로 굴러간다: 경보 단계(주의/경계/심각), 가구 상태머신(미확인→무응답→방문큐→…), 확인 결과 코드. SQLite 제약으로 DB enum을 못 쓰기 때문에([ADR-0004](0004-sqlite-prisma.md)) 오타 하나가 상태머신 버그가 된다. 또한 여러 사람과 AI 에이전트가 병렬로 작업하므로 타입이 곧 모듈 간 계약서 역할을 해야 한다.

## 결정 (Decision)

**TypeScript, `strict: true`** (create-next-app 기본값 유지). 도메인 상태값은 `src/lib/domain.ts`의 `as const` 객체로만 정의하고, 문자열 리터럴 직접 사용을 금지한다.

## 근거 (Rationale)

- DB가 못 잡는 enum 오타를 컴파일 타임에 잡는다
- 스코어링 입력/출력, 상태 전이 함수의 시그니처가 곧 스펙 — 리뷰·에이전트 협업 비용 감소

## 검토한 대안 (Alternatives)

- **JavaScript** — 48h에 빠를 것 같지만 상태머신·스코어링 버그 디버깅으로 더 느려짐. 기각
- **strict 해제** — 얻는 것 없음. 기각

## 결과 (Consequences)

- 긍정: 상태값·가중치 오용이 빌드에서 걸러짐
- 부정/트레이드오프: 외부 API 응답 타이핑에 약간의 초기 비용 (필요 필드만 최소 타이핑으로 완화)
- 되돌리기: `tsconfig.json` 한 줄이지만, 되돌릴 이유가 생기면 안 된다
