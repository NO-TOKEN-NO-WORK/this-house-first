# ADR-0017: 알림 이벤트를 저장하고 Web Push로 전달한다

- **상태**: 승인됨
- **날짜**: 2026-08-22
- **결정자**: 팀 전원
- **대체**: [ADR-0008](0008-notification-in-app-first.md), [ADR-0006](0006-pwa-manual-service-worker.md)의 Service Worker scope 결정

## 맥락 (Context)

PRD F3는 경보일 오전 8시 담당자 요약을, F4는 무응답 2회·이상 징후의 방문 승격 시 관리자 알림을 요구한다. 인앱 배너만으로는 앱을 열기 전 알림을 전달할 수 없고, 승격 이벤트 피드와 중복 발송 원장도 아직 없다. 알림 생성과 전달을 분리해야 비경보일 침묵과 `요약 1건 + 승격 이벤트만` 정책을 수단과 무관하게 지킬 수 있다.

## 결정 (Decision)

- `Notification`을 알림 원장으로 저장하고 `eventKey` 고유 제약으로 경보일·수신자별 아침 요약과 경보일·대상자별 승격을 한 번만 만든다.
- 자동 예보 재선언은 기존 요약의 내용만 갱신한다. 관제 센터에서 관리자가 경보 단계 버튼을 누른 수동 재선언은 명시적인 재전송 요청으로 보고, 해당 경보일의 담당자 요약 Push 상태만 초기화한다. 승격 이벤트는 다시 열지 않는다.
- 실제·미래 경보 사건은 해당 경보일 자정에 만료한다. 과거 날짜 수동 데모는 시연 당일 자정까지만 유효하게 해 즉시 전달하되, 구독이 없었던 알림을 다음 날 뒤늦게 보내지 않는다.
- `PushSubscription`을 담당자/관리자 계정에 연결해 여러 기기를 지원한다. v0에 인증이 없으므로 기존 화면의 `workerId` 문맥을 그대로 사용하며, 실배포 전에 인증·권한 검사를 추가한다.
- Web Push 암호화·VAPID 처리는 Next.js 16 공식 PWA 가이드가 사용하는 `web-push` 패키지로 구현한다. 공개키만 `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, 비밀키와 연락처는 서버 전용 환경 변수로 둔다.
- 수제 Service Worker는 유지하되 알림을 관리자 화면에서도 받을 수 있도록 등록 scope를 `/`로 넓힌다. fetch 캐시는 계속 `/today` 경로에만 적용해 관리자 화면을 오프라인 캐시에 섞지 않는다.
- 외부 Push 전송은 DB 트랜잭션 밖에서 수행한다. 알림 원장은 상태 전이와 같은 트랜잭션에 기록하고, 전송 실패는 원장을 남긴 채 재시도할 수 있게 한다.
- 잠금 화면에는 전체 주소·건강정보·위험 사유를 싣지 않는다. 알림은 합성 이름 또는 건수와 행동만 표시하고 상세는 앱 딥링크에서 확인한다.

## 근거 (Rationale)

- 상태 전이와 알림 원장의 원자성을 보장하면서 느리고 실패 가능한 외부 네트워크 호출을 트랜잭션에서 분리할 수 있다.
- 고유 이벤트 키는 수동 재발령·HTTP 재시도·동시 기록에서 중복 알림을 막는다.
- 같은 이벤트 원장을 인앱 피드와 Push가 공유하므로 전달 수단별로 정책이 달라지지 않는다.

## 검토한 대안 (Alternatives)

- 인앱 알림만 유지 — 앱을 열기 전 승격을 알 수 없어 이번 요구를 충족하지 못한다. 기각
- FCM — 네이티브 앱이 아니고 별도 플랫폼 의존이 생긴다. 기각
- DB 기록 없이 상태 변경 직후 바로 Push — 전송 실패·재시도·중복 방지와 인앱 피드를 구현할 수 없다. 기각

## 결과 (Consequences)

- 긍정: 경보일 아침 요약과 방문 승격이 영속 이벤트, 인앱 피드, Web Push에서 일관되게 동작한다.
- 부정/트레이드오프: VAPID 키 설정과 사용자 구독 동의가 필요하다. 인증 전 v0의 구독 소유권은 데모 수준이다.
- 운영: Vercel Cron이 매일 `23:00 UTC`(08:00 KST)에 `availableAt`이 지난 미발송 이벤트를 처리한다. Hobby 플랜은 일 단위 실행 시각이 한 시간 범위로 지연될 수 있고, 수동 데모 발령은 예약을 기다리지 않고 즉시 발송한다.
- 운영: 수동 발령 직후 발송기는 새로 선언한 `alertDayId`만 처리하며 기기별 성공·실패와 미구독 담당자 수를 관리자 화면에 반환한다.
