# PRD: 이 집 먼저 (This House First)
**폭염·한파 위험도 기반 취약노인 알림·대응 관제 시스템**
v0.1 — JunctionX Korea 2026 (48h MVP)

---

## 1. 개요

기온이 임계값을 넘는 날, 돌봄 대상 어르신 개개인의 위험도를 계산해 담당 생활지원사에게 알림을 보내고, **전화 확인 → 무응답·이상 시 방문**의 대응 사다리를 자동으로 짜주는 시스템.

**한 줄**: "오늘 누가 위험한지, 누구부터 확인할지, 언제 방문으로 전환할지"를 정해주는 폭염 관제.

## 2. 문제 (검증 완료)

| # | 사실 | 근거 |
|---|---|---|
| P1 | 온열질환 사망의 62%가 80세 이상, 80세 이상은 집 안 발생이 전체의 3배(18% vs 7%) | 복지부·질병청 2026.8 |
| P2 | 위험은 예측 가능: 연령(발생률 전연령 최고), 건물(꼭대기층 OR 4.1, 단열 부재, 1975년 이전), 기온(체감 38도 시 노인 사망위험 +19%) | 질병청 / Vandentorren 2006 |
| P3 | 생활지원사 1인당 평균 15명(지침 명문화), 주 25시간, 방문은 하루 약 4가구 → 전원 방문에 4일 | 복지부 사업안내 p.78 / 현장 사례 |
| P4 | 환자의 30%가 12일에 집중 — 피크일에 15명 동시 확인 수요 발생, 처리 능력은 순차적 | 질병청 |
| P5 | 지침상 일 단위 확인 순서·강도를 정하는 규정과 도구가 없음. 혹서기 대응은 "전원 일괄 강화" | 복지부 사업안내 전수 확인 |
| P6 | 명부+경보+방문을 갖춘 시스템은 사망을 68% 줄인 실증 있음(프랑스 2006, -4,400명). 한국은 부품은 다 있고 배분 로직만 없음 | Fouillet 2008 |

## 3. 목표 / 비목표

**목표**
- G1. 폭염(한파) 경보일에 담당자가 15명 전원의 안전을 **당일 안에** 확인하게 한다
- G2. 방문이라는 희소 자원을 무응답·이상·초고위험 가구에 집중시킨다
- G3. 확인 결과가 다음 날 위험도에 반영되는 학습 루프를 만든다

**비목표 (v0에서 안 함)**
- 센서·IoT 설치, AI 음성 자동전화 (기존 서비스와 중복, 사후 감지 영역)
- 사망 예측 정확도 경쟁 (목표는 예측이 아니라 배분)
- 대상자용 앱 (사용자는 담당자와 관리자만)
- 실명 대상자 데이터 (합성 데이터로 시연)

## 4. 사용자

| 페르소나 | 설명 | 핵심 니즈 |
|---|---|---|
| **담당자** (생활지원사, 50~60대) | 주 25시간, 15명 담당, 스마트폰 사용 가능하나 복잡한 UI 어려움 | "오늘 누구부터, 뭘 하면 되는지"만 명확히. 기록은 원터치 |
| **관리자** (전담사회복지사/시군 복지과) | 담당자 10~17명 관리, 특보 시 상부 보고 의무 | 미확인 고위험 가구 실시간 파악, 보고용 현황 |

## 5. 핵심 플로우

### F1. 트리거 (시스템)
- 매일 17시, 기상청 단기예보로 익일 읍면동별 최고 체감온도 조회
- 3단계 판정: **주의**(폭염특보 수준) / **경계**(체감 35도+) / **비상**(중대경보, 체감 38도+ — 화면 문구는 ADR-0019)
- 임계값 미달 시: 시스템 침묵 (알림 피로 방지 — 평상시엔 조용한 게 스펙)

### F2. 스코어링 (시스템)
- 대상자별 위험점수 = 개인 취약도 × 건물 취약도 × 당일 기상계수 (상세 §7)
- 위험 단계(심각·경계·주의) 분류: **심각**(초고위험) / 경계(고위험) / 주의(중위험)

### F3. 아침 알림 (담당자 앱)
- 경보일 아침 8시 푸시: "오늘은 폭염 비상 단계입니다. 김○○님 외 2명이 특히 위험합니다"
- 앱 첫 화면 = 오늘의 대응 보드:
  - 심각: **전화 생략, 오전 방문** (전화로 '괜찮다'를 신뢰할 수 없는 군 — 질병청 "고령자는 초기 증상 자기 인지 어려움")
  - 경계: 오전 중 전화
  - 주의: 15시 이전 전화
- 각 대상자 카드에 위험 사유 표시: "1938년생·독거 / 1972년 단독주택·슬레이트 / 오늘 체감 38도" — 설명 가능성이 신뢰의 조건

### F4. 에스컬레이션 (시스템 + 담당자)
- 전화 결과 원터치 기록: `정상` / `무응답` / `이상 징후` / `연락두절`
- 승격 규칙: 무응답 2회(30분 간격) 또는 이상 징후 → **방문 큐로 자동 승격** + 관리자 알림
- 방문 큐에 2건 이상 쌓이면: 위험도 우선 + 이동시간 최소 순서로 출동 경로 제시 (동선최적화는 여기서만 등장)
- 방문 결과 기록: `정상` / `조치함(냉방 가동·수분 등)` / `119 연계` / `에어컨 없음·고장` (→ 지원사업 연계 플래그)

### F5. 관제 대시보드 (관리자)
- 지도 뷰: 건물 단위 위험 히트맵 + 가구 상태 색상 (미확인/전화완료/방문중/조치완료/연락두절)
- 핵심 위젯: "미확인 심각 가구 수" — 이 숫자가 0이 되는 게 그날의 목표
- 일일 리포트 자동 생성 (특보 시 상부 보고 의무 대응)

## 7. 위험도 모델 v0 (규칙 기반, 설명 가능)

```
위험점수 = W_개인 × W_건물 × W_기상

W_개인:  연령 (80+ = 3.0, 75-79 = 2.0, 65-74 = 1.0)   ← 사망 62%가 80+
        × 독거 (1.5)                                  ← 프랑스: 고립 고위험
        × 거동불편/기저질환 (2.0, 데이터 있을 시)        ← OR 7.5
W_건물:  단독주택 (1.4)                                ← 건축공간연구원 1.4배
        × 1980년 이전 건축 (2.0), 1980-99 (1.5)        ← 단열 부재가 주거요인 1위
        × 최상층/옥탑 (2.0, 데이터 있을 시)             ← OR 4.1
W_기상:  주의 (1.0) / 경계 (1.5) / 비상 (2.5)          ← 체감 38도 시 +19%
```

- 모든 가중치에 출처를 코드 주석으로 명기 → "가중치 어떻게 정했나" 질문 방어
- ML 아님을 명시: v0는 근거 기반 규칙. 실데이터 축적 후 재학습이 로드맵

## 9. 비기능 요구사항

- 담당자 앱은 60대가 쓸 수 있어야 함: 글자 크게, 화면당 결정 1개, 탭 2회 이내 기록 완료
- 알림 피로 방지: 비경보일 알림 0건, 경보일도 요약 1건 + 승격 이벤트만
- 오프라인 내성(농촌 음영지역): 기록 로컬 큐잉 후 동기화 — 데모에선 언급만

## 10. 데모 시나리오 (5분)

1. **평상시 화면**: 조용함. "저희 시스템은 평소엔 아무것도 안 합니다" (한 줄 웃음 포인트)
2. **8/21 비상 발령**: 관리자 지도가 빨갛게 물듦 → 담당자 앱에 알림 도착
3. **담당자 시점**: 위험 단계가 심각한 2명은 방문 지시 + 사유, 경계·주의 단계는 전화 목록 → 전화 기록 시연
4. **에스컬레이션**: 박○○님 무응답 2회 → 방문 큐 승격 → 출동 경로 표시
5. **발견**: 방문 기록 "에어컨 고장" → 익일 위험도 상승 + 지원사업 연계 플래그
6. **시뮬레이션 슬라이드**: 무작위 확인 vs 위험도 확인 — 프로필 기반 사전 계산 43.9% 감소. 경북 실 건축물대장 시드 후 `npm run db:seed` 출력값으로 교체
7. **클로징**: "프랑스는 이 구조로 사망을 68% 줄였습니다. 한국은 부품이 다 있고, 이 로직만 없습니다"

## 11. 성공 지표 (실배포 가정)

- 북극성: **경보일 내 위험 단계가 심각한 가구 확인 완료율** (목표 100%, 현재는 측정조차 불가)
- 보조: 첫 확인까지 시간(중앙값), 무응답→방문 전환 소요시간, 에어컨 미보유·고장 발굴 건수
- 반(反)지표: 담당자 알림 무시율 (알림 피로 감지)

## 12. 리스크

| 리스크 | 대응 |
|---|---|
| 전화 '괜찮다'의 허위 안심 | 위험 단계가 심각한 가구는 전화 생략·방문 우선 설계로 원천 차단 |
| 알림 피로 | 트리거 임계값 + 상위 N명만 강조 + 비경보일 침묵 |
| 개인정보 | B2G 전제, 데모는 합성. 실배포 시 지자체 위탁 계약 내 처리 |
| 가중치 정확도 공격 | 전 가중치 출처 명기 + "랭킹은 예측보다 쉬움, 현행(무작위)보다 나으면 됨" |
| 담당자 수용성 | 업무 추가가 아니라 기존 '특보 시 안부확인' 의무의 도구화임을 강조 |

## 13. 48시간 작업 분배 (참고)

- **D1 오전**: 합성 데이터 15명 + 건축물대장·기상 API 파이프라인
- **D1 오후**: 스코어링 엔진 + 에스컬레이션 상태머신
- **D1 밤**: 담당자 모바일 웹 (대응 보드·기록)
- **D2 오전**: 관리자 지도 대시보드
- **D2 오후**: 출동 경로(Should) + 데모 시나리오 리허설 + 시뮬레이션 계산
